# Desktop Companion Agent Design Principles

# 1. 核心原则

## 1.1 角色不是工具

Agent 不只是回答问题。

它需要：

-   状态
-   人格
-   记忆
-   行为

------------------------------------------------------------------------

## 1.2 人格不等于权限

必须遵守：

    Character Intent != System Permission

任何主动行为都不能绕过安全限制。

------------------------------------------------------------------------

## 1.3 真实与虚构分离

角色可以拥有：

-   今日想法
-   临时幻想
-   虚构生活感

但是：

这些内容不能影响：

-   用户资料
-   事实判断
-   工具执行

------------------------------------------------------------------------

## 1.4 本地能力优先

不能依赖单一 API。

必须支持：

-   离线运行
-   本地模型
-   云端增强

------------------------------------------------------------------------

## 1.5 模块解耦

模块之间通过：

-   Event
-   Interface
-   Adapter

连接。

避免：

一个功能变化导致整个系统重写。

------------------------------------------------------------------------

# 2. 设计思想

## 从聊天转向陪伴

传统：

    User
     ↓
    Question
     ↓
    AI
     ↓
    Answer

本项目：

    Environment
     ↓
    Understanding
     ↓
    Internal State
     ↓
    Decision
     ↓
    Interaction

------------------------------------------------------------------------

# 3. 主动行为原则

主动不代表频繁。

需要考虑：

-   用户是否忙
-   是否重要
-   是否重复
-   是否合适

------------------------------------------------------------------------

# 4. 安全原则

默认：

-   最小权限
-   用户确认
-   可查看
-   可撤销

------------------------------------------------------------------------

# 5. 扩展原则

未来增加：

-   新模型
-   新角色
-   新 Avatar
-   新工具
-   新感知能力

不应该破坏核心系统。
